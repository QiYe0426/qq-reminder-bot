## B1.2.6 Schema Alignment & Drift Guard（2026-07-12）

四个 Shadow PASS 工具的 handler-shaped canonical fixtures 已建立，inventory 已从简化顶层
字段扩展为真实 data schema。`OutputReducerInventoryItem.optional_paths` 用于明确
branch-specific/optional 字段，不会授权 reducer。

| Tool | 必有 data 字段 | Optional / branch-specific | Candidate | Blocked semantics |
|---|---|---|---|---|
| `generate_daily_report` | group_id, date, filename, report, truncated, preview_chars, reused_existing | image_filename、pdf_filename 仅 existing-report 分支 | report | identity、date、files、count、truncation/state |
| `build_semantic_graph` | graph/group ID, scope, source_key, title, keyword, message/node/edge counts, nodes, edges, generated_at, summary | node message/mention count、edge turn count metadata | summary | identity、scope/source、topology、counts、time |
| `get_semantic_graph` | graph/group ID, scope, source_key, title, keyword, message/node/edge counts, nodes, edges, updated_at, summary | decoded node/edge metadata count keys | summary | persisted identity、scope/source、topology、counts、time |
| `render_semantic_graph` | graph/group ID, image_filename, image_path, sent, send_error, summary | 无缺失 output 字段；summary 来源有 persisted/regenerated 两分支 | summary | identity、file path/name、delivery state/error |

日报 fixture 覆盖 existing files、新生成缺少 image/PDF、handler 已截断长 report；report
字符截断发生在 handler，未来 byte reducer 只负责其后的 canonical serialized budget。
Build/get fixture 覆盖正常、长 summary、可选 metadata 缺失。Render fixture 覆盖 source
summary、`graph_result.summary` 为空时 regenerated summary、发送成功/未发送/发送失败。

语义图不存在独立顶层 topic/speaker/media count。Person/topic 由 `nodes[].kind` 表达，
message/mention/turn count 位于 node/edge metadata；当前 schema 没有 media count。
Canonical `message` 位于 ToolResult 顶层，由 tool contract 保护，不列入 data inventory。

Drift guard 递归枚举 fixture data path，并用 `[]` 表达 list item shape。任何未知顶层或嵌套
字段都会失败；candidate 必须实际存在或显式 optional；blocked/candidate 继续互斥；REVIEW
工具仍不能生成 proposal。

Proposal 已更新为 `schema_aligned_pending_registration_review`。`get_semantic_graph` 与
`render_semantic_graph` 的 5000-byte budget 已存在于 metadata，但仍未授权 capability 或
reducer；`generate_daily_report` 与 `build_semantic_graph` 的 5000 bytes 仍只是建议，必须
基于 handler-shaped size distribution 单独审批。固定受保护结构超过预算时必须返回
original，不能为满足预算删除 graph topology、files、counts 或 delivery state。

新增 schema alignment 测试 17 个；Output Governance 定向 103 passed in 4.31s；完整
pytest 421 passed in 29.74s；compileall 和 `git diff --check` 通过。未提交 commit。
`OUTPUT_BUDGET_REDUCERS`、`OUTPUT_REDUCER_CAPABILITIES` 仍为空，enforcement 未开启。

## B1.2.5 Disabled Capability Review（2026-07-12）

本阶段新增独立、只读的 `OUTPUT_REDUCER_CAPABILITY_PROPOSALS`。它不是
`OUTPUT_REDUCER_CAPABILITIES`，不被 Gateway 读取，不创建 reducer，也不授权 production
registration。四个 proposal 当前统一标记为 `requires_schema_alignment`。

| Tool | candidate path | reducer | 保留信息 | 丢弃信息 | 风险 | recommendation |
|---|---|---|---|---|---|---|
| `generate_daily_report` | `data.report` | `TextReducer` | 日期、群、文件名、truncated、preview_chars、reused_existing、message | 仅 report 尾部展示文本 | 高：两个成功分支字段不完全相同，且 metadata 尚无 output budget | 完整枚举成功 schema，并单独审批 output budget 后再注册 |
| `build_semantic_graph` | `data.summary` | `TextReducer` | graph/group identity、scope/source、title/keyword、计数、nodes、edges、时间、message | 仅 summary 尾部展示文本 | 高：inventory 未覆盖完整 graph schema，且 metadata 尚无 output budget | 对齐 build schema，并单独审批 output budget 后再注册 |
| `get_semantic_graph` | `data.summary` | `TextReducer` | graph/group identity、scope/source、title/keyword、计数、nodes、edges、updated_at、message | 仅 summary 尾部展示文本 | 中高：已有 5000-byte budget，但 inventory 未覆盖完整 persisted graph schema | 对齐 load schema 后可进入逐工具注册评审 |
| `render_semantic_graph` | `data.summary` | `TextReducer` | graph/group identity、image filename/path、sent/send_error、message | 仅 summary 尾部展示文本 | 高：已有 5000-byte budget；delivery/file 字段不可变，summary 来源存在 fallback 分支 | 补齐 render schema 和 summary 来源分支测试后可进入逐工具注册评审 |

Proposal 内容：

```text
generate_daily_report: data.report, TextReducer, max_chars=6000,
  proposed_budget_bytes=5000, requires_schema_alignment
build_semantic_graph: data.summary, TextReducer, max_chars=None,
  proposed_budget_bytes=5000, requires_schema_alignment
get_semantic_graph: data.summary, TextReducer, max_chars=None,
  proposed_budget_bytes=5000, requires_schema_alignment
render_semantic_graph: data.summary, TextReducer, max_chars=None,
  proposed_budget_bytes=5000, requires_schema_alignment
```

`max_chars=None` 表示 capability 不另设字符上限，实际约束继续使用 canonical UTF-8 JSON
bytes；日报保留 handler 已存在的 6000-character 上限。5000 bytes 只是后续审批输入：对
`get_semantic_graph` / `render_semantic_graph` 与当前 metadata 一致；对另外两个工具不构成
metadata 修改或批准。

预算边界验证：

- A：candidate 长文本导致超预算且固定结构可容纳时，允许 deterministic reduction；
- B：candidate 置空后固定结构仍超预算时，`TextReducer` 返回 original；
- C：candidate 类型变化为不可缩减值、reduction 后仍超预算时，返回 original。

跨版本审核发现 candidate path 本身较稳定：日报 adapter 显式生成 `report`，三个语义图
adapter 显式生成或补全 `summary`。主要风险不是路径当前缺失，而是业务新增字段后 inventory
不会自动更新。当前 inventory 的 semantic graph `output_structure` 未列出实际存在的
`scope`、`source_key`、`title`、`keyword`、计数字段及 `generated_at` / `updated_at`；日报
读取既有文件与新生成分支的 image/pdf 字段也不同。因此在 schema 对齐与分支 fixture 测试
完成前，不建议进入实际 B1.3 production registration。

新增文件：

- `plugins/agent_tools/output_reducer_capability_review.py`
- `tests/test_agent_tool_capability_review.py`

验证结果：新增测试 7 passed in 1.64s；Output Governance 定向 86 passed in 5.16s；
`compileall` 通过；完整测试 404 passed in 30.34s；`git diff --check` 通过。修改未提交。

## B1.2 Shadow Reduction Sample Validation（2026-07-12）

已为四个 ALLOW 工具增加人工 canonical `ToolResult` 超预算样本，并在现有 shadow-only
evaluator 上完成逐工具验证。样本覆盖长 summary/report、长 description、多段文本列表和
嵌套 `data`；没有构造 execution、confirmation、idempotency、URL、resource ID 或
message ID。预算按“candidate 置空后的固定结构 bytes + 600 bytes”设置，确保固定结构可
容纳且超预算来源可归因于候选长文本。

| 工具 | candidate path | before bytes | after bytes | reduction ratio | 结果 |
|---|---|---:|---:|---:|---|

| `render_semantic_graph` | `data.summary` | 28380 | 12980 | 54.26% | PASS |

## B1.2 Runtime Shadow Reduction Audit

B1.2 在 Gateway 的 normalized ToolResult measurement 后增加 shadow-only evaluator。
Reducer 来源是独立、显式、只读的 `OUTPUT_BUDGET_SHADOW_REDUCERS`，并在运行前核对
inventory 的 ALLOW status 和 candidate paths。当前显式范围是日报 `report` 和三个语义
图工具的 `summary`；只有 metadata 声明预算且结果实际超限时才评估。

每次 shadow evaluation 对深拷贝 original 执行两次 reducer，用于比较 determinism；
canonical rebuild 和 protected fields 继续由 Output Budget framework 校验。Telemetry
只记录 tool name、reducer type、before/after bytes、reduction ratio 和 status，不记录
结果、参数、用户/群身份或 Prompt。Reducer failure、invalid output、non-determinism 或
telemetry exception 均不影响 original result。

Runtime 不变量：Handler 仍只执行一次；shadow candidate 不替换返回、不进入 failure
classification、不写入 idempotency cache；first result 与 replay 保持原结果一致。
Production registry 仍为空，enforcement flag 默认关闭。B1.2 尚未提交。

## 2. 架构变化

Output Budget framework 在 Handler 结果 normalize 后测量 canonical ToolResult 的 UTF-8
JSON bytes。只有 flag 开启、预算超限且存在显式 reducer 时才会尝试 reduction；失败或
非法结果回退原结果。`TextReducer` 只处理配置的 `data` 路径，按 Unicode code point
裁剪并 canonical rebuild。

本阶段新增的 `OutputReducerInventoryItem` 是 frozen audit record：

```text
Registered AgentTool
  -> explicit canonical data structure audit
  -> candidate paths / blocked paths
  -> risk level / review status
  -> future disabled capability proposal
```

Inventory 不连接 Gateway，不创建 reducer，不从 ToolResult 自动推断路径。

## 3. Runtime 不变量

- Authorization 顺序和 legacy AND metadata 行为不变。
- Confirmation decision 和 token lifecycle 不变。
- Idempotency claim、cache、unknown 和 replay 不变。
- Handler 不因 Inventory 重复执行。
- first result、cache 和 replay 的既有一致性不受影响。
- 用户可见输出不变。

## 4. 安全约束

- candidate、blocked 和 output structure 路径必须位于 `data` namespace。
- candidate 与 blocked 路径不得重叠。
- error、execution、idempotency 和 confirmation 顶层语义不能成为候选。
- resource/file/task/message ID、URL、delivery state 和配置状态被明确阻止或拒绝。
- Inventory 与 capability 均为 frozen dataclass，registry 为只读映射。
- Inventory deterministic，不扫描字符串，无数据库、网络或其他副作用。
